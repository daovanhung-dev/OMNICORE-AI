# Diagrams, assets and imports

Diagrams can be Mermaid: context, sequence, activity, ERD, state. Each diagram identifies actor, trigger, guard, data owner, transaction and external system; an inferred relationship must be labelled `PROPOSED`.

Assets have path, designer/source, version, state variant, license/rights, status and mapping to View IDs. Do not fabricate a screenshot from unrelated designs to satisfy approval.

Imports: module/feature source ownership; external package adapters; API models & DTOs; migration/test files; separate existing vs planned paths. Do not force a generic folder structure onto source with different architecture.
